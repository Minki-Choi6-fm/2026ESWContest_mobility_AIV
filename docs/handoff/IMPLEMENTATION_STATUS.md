# 구현 상태 표 (S11-a) — 어디까지 "실제 하드웨어로" 확인했는가

범례: **HW** = 실제 하드웨어(레이더/STM32/Pi5 등)로 검증됨 · **재생/모의** = 녹화 로그 재생, 가짜 STM32(pty), mock, 합성 데이터만 · **미검증**.
"HW"는 *동작*을 봤다는 뜻이지 *정확도*(정답과 비교)를 쟀다는 뜻이 아닙니다. 정답 라벨/줄자 측정은 하나도 없습니다.

| 단계 | 상태 | 근거(사실) | 미검증 이유 → 검증에 필요한 것 |
|---|---|---|---|
| STM32 수신 (레이더 CAN→MCP2515→UART→Pi5 디코드, 0x10~0x14) | **HW** (일부 한계) | 10/16 주행 3개 로그 + 10/25 책상(v18c, v18d2)에서 실제 프레임을 디코드(불량 프레임 통계는 live_receiver 기록 참조). CAN 칩 넘침으로 물체 프레임 3~7 % 손실, 전원 처짐 시 레이더 끊김 | 레이더 12 V 전원이 불안정(XL6009 입력 4.5→3 V대)하여 "정상 상태" 기준 측정이 아직 없음 → 안정된 12 V 전원으로 재측정(사용자, 멀티미터/벤치 전원) |
| 타깃 선택 (차선 폭, 유지/교체, 측면 차선, 끼어들기) | **재생/모의** | 10/16 실제 레이더 로그를 오프라인 재생 + 단위 시험. 실시간 STM32 입력 리허설은 준비만 하고 아직 안 돌림(`DESK_REHEARSAL.md`) | 정답 라벨 없음, 끼어들기/측면 주행 시나리오를 실차로 만든 적 없음 → 앞차 1대와 폐쇄된 곳에서 주행 시험(사람 2명, 차 2대) |
| 거리/상대속도 | **HW (값만)** / 정확도 **미검증** | 레이더가 준 값을 그대로 사용(로그에서 연속성 확인). 줄자·GPS와 비교 안 함 | 기준 거리 측정이 없음 → 정지 상태에서 줄자로 3·5·10 m에 금속판 놓고 비교(사용자 1명, 줄자) |
| 위험 판단 (필요 감속도/TTC/억제 규칙/히스테리시스) | **재생/모의** | 단위 시험 + 10/16 로그 재생(레벨 분포 비율만 있고 정답 없음). 수치(0.7·K·g 등)는 전부 [PROPOSAL] | 정답(실제 위험)이 없음, 급제동 시나리오 실측 없음 → 폐쇄 구간 접근/급제동 시험 + 판정 기준 합의(팀) |
| K (운전자 평소 제동) | **재생/모의** | 로그 3개에서 인정 이벤트 2/0/0개 → 숫자 근거 없음(기본 0.5는 계산용, 미광고) | 이벤트 3개 이상 필요 → OBD 속도가 있는 상태에서 평소 감속 주행(사용자, 실차) |
| 자차 속도 (OBD 우선, GPS 대체) | **HW 일부** | 10/16 OBD 속도 정상 수신. 10/25 책상은 OBD 없음, GPS도 fix 없음(WARN) → 속도 "없음" 경로만 | 책상에 OBD/GPS 신호 없음 → 실차(OBD) 또는 야외(GPS fix) |
| BSM 생성 | **HW 입력 + 로컬 출력** | 실제 센서값으로 필드 생성은 재생에서, 인코드/디코드는 앞차 코드와 루프백으로 확인(`FRONT_COMPAT_TEST.md`) | — |

## 한 줄 요약
실제 하드웨어로 "프레임이 들어오고 해석된다"까지만 확인했고, 위험 판단·K·BSM 송수신(무선)·카메라·부저는 모두 재생/모의/루프백 수준입니다. 레이더 전원이 불안정한 동안은 HW 측정 자체의 기준선이 흔들립니다.
