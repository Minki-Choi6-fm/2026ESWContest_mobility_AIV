# pub < b, ovf, exp 대비 b 부족 — 코드 조사 (S11-d, 읽기 전용; 기준: main_v18d2_final_proposed.c = v18c와 같은 수신부)

## 1) pub 이 b 보다 작은 이유 (예: b=154, pub=110)
- `b`(rad_nb)는 CAN 에서 0x60B 프레임을 **받을 때마다** 센다(약 608행). `pub`(rad_npub)는 그 뒤 **필터를 통과해 `radar_publish()` 를 부른 것만** 센다(약 656행).
- 필터는 두 개: (1) 차량 클래스 필터 `if (!TEST_ALL_CLASSES && objClass != 1)` — 이 빌드는 `TEST_ALL_CLASSES 1` 이라 **꺼져 있음**. (2) **노이즈 필터 `rcs >= -5.0 dBsm`** — 반사강도가 −5 dBsm 미만인 물체는 `rad_npub++` 도 `radar_publish()` 도 건너뜀.
- 그래서 `b − pub` = 이 초에 받은 0x60B 중 **RCS < −5 dBsm 인 물체 수**. 예의 154→110 이면 약 44개(29 %)가 약한 반사. `veh`(차량 클래스 수)는 별개 카운트이며 pub 과 직접 관계가 없다.
- `pub` 은 UART 큐에 넣기 전에 센다. TX 큐가 가득 차서 버려진 프레임은 `txdrop=`(v18d2에서 추가) 로 따로 나온다 → pub 감소 원인이 아니다.
- 한계: 154→110 의 RCS 분포 실측은 이 PC 에 로그가 없어 못 봤다(코드 설명). 확인하려면 `OBJ ... rcs=` 줄 또는 `radar.csv` 의 rcs 열에서 −5 미만 비율을 센다.

## 2) MCP2515 수신 버퍼 넘침(ovf)에서 오류 플래그를 지우는 코드가 있는가
있다, 그런데 **빌드 설정에 따라 달라진다.**
| 위치 | 내용 |
|---|---|
| `mcp2515_read_orig()` (약 1792~1794행) | 프레임을 읽을 때마다 EFLG(0x2D) 의 RX0OVR/RX1OVR(0xC0) 을 읽어 `rad_ovf++` 하고 `mcp_bitmod(0x2D, 0xC0, 0)` 로 지움 — **프레임 단위** |
| `mcp2515_read_fast()` (약 1815~1830행) | **EFLG 를 읽지도 지우지도 않음** (CANINTF 만 지움). `FAST_MCP_READ` 기본값이 **1** 이라 이 빌드는 이 경로 |
| RADSTAT 1초 블록 (약 717행) | `if (radar_dbg_read(0x2D) & 0xC0) { rad_ovf++; radar_dbg_clear_ovf(); }` — **1초에 한 번** 확인·지움 (`radar_dbg_clear_ovf()`, 약 1856행) |
- 결론: 현재 빌드에서 `ovf` 는 **"넘침이 한 번이라도 있었던 초의 수"**(소스 주석도 같은 설명)이다. 플래그가 1초 동안 유지되므로 "거의 매초 증가" = 거의 매초 최소 한 번 넘침이 발생. **몇 프레임이 사라졌는지는 알 수 없다.**
- MCP2515 는 RX 버퍼가 2개(RXB0→롤오버→RXB1)뿐이라 두 개가 찬 상태에서 세 번째 유효 프레임이 오면 새 프레임이 버려지고 EFLG 넘침 비트가 선다(데이터시트 일반 동작, 이 칩 동작을 보드에서 직접 본 것은 아님).

## 3) exp 대비 b 가 3~7 % 적은 것 — 코드로 설명되는가
- `exp`는 받은 **0x60A 의 "이번 사이클 물체 수" 합**(약 610행), `b` 는 실제 받은 0x60B 수. 따라서 `exp − b` 는 **CAN 칩(MCP2515)이 받지 못했거나 읽기 전에 버려진 0x60B 수**(+ 1초 경계에서 사이클이 둘로 갈리는 오차)이다.
- **UART 송신은 원인이 아니다**: b 는 `radar_publish()`/`proto_send()` 보다 앞(CAN 수신 직후)에서 센다. TX 큐 가득 참은 pub 이후 단계(txdrop)다.
- 후보 원인(코드 근거): ① 물체 프레임이 한 사이클에 한꺼번에(최대 64개 등) 오는데 칩 버퍼가 2개뿐 → 메인 루프가 늦게 돌면 넘침(LOOP max 9 ms 로그, `RAD_BATCH 24`, `RAD_SPIN_US 400` 로 한 번에 모아 읽음). ② 처리(OLED/IMU/OBD 등)로 SPI 읽기가 늦어짐. ③ 프레임 자체가 전원 처짐/배선으로 손실(전원 문제와 혼합 가능).
- 10/16 로그 상관(재생, 사실): 물체 많은 초(exp≥100)에서 (exp−b)/exp 평균 4.4 % (141541), 3.3 % (151202), 2.2 % (152211). `ovf` 가 늘어난 초 vs 안 늘어난 초의 부족률: 151202 는 6.4 % vs 1.1 %, 152211 는 5.3 % vs 0.4 % (**넘침이 있는 초에 부족률이 크게 높다** — 칩 넘침 설명과 일치), 141541 은 4.4 % vs 4.6 %(ovf 가 82 % 초에서 증가해 구분 힘이 약함). 상관일 뿐 인과 증명은 아님.
- 줄이는 후보(제안, 적용 안 함): 칩 인터럽트(INT) 우선 처리 강화/ 읽기 루프를 다른 작업보다 앞에, `read_fast` 에도 넘침 카운트 추가(지금은 초 단위라 정량화 불가), MCP2515 RXB0 BUKT 롤오버 설정 확인.
