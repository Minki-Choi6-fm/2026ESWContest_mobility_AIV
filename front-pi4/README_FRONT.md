# 전방차 고도화 — 후방차에 정보 보내기 + 후방차 경고 받기

전방차 라즈베리파이의 `~/v2v/` 폴더에 그대로 덮어쓰면 됩니다. 팀 V2V 코드(`bsm_protocol.py`, `transport.py`, `freshness.py`, `v2v_node.py`)와 UART 파서(`aiv_uart_rx.py`)를 그대로 재사용합니다.

## 무엇을 하나

```
  GPS(gpsd) ─┐
  STM32 ─────┼─> 전방차 BSM (위치·속도·진행방향·급제동) ─> ESP32 ─> 후방차
  (OBD/IMU)  │
             └<─ 후방차 BSM (위험 경고) <─ ESP32
                   └─ '내 뒤의 차'가 보낸 경고면 STM32 로 0x20 경고 명령 -> 부저/OLED
```

1. **후방차가 필요한 정보 보내기**: 기존 `v2v_node.py`는 위치·속도만 보냈습니다. 이제 **급제동 여부**를 함께 보내서, 후방차가 레이더보다 먼저 전방차 급정지를 알 수 있습니다.
2. **후방차 경고 받기**: 받은 경고가 정말 **내 뒤에서 같은 방향으로 오는 차**가 보낸 것인지 GPS로 확인한 뒤, STM32에 경고 명령을 보냅니다. 옆 차선, 앞쪽, 반대 방향, 100m 넘게 먼 차의 경고는 무시합니다.

## 입력 우선순위 (하나가 끊겨도 계속 동작)

| 값 | 1순위 | 2순위 |
|---|---|---|
| 속도 | STM32의 OBD 차속(`0x14`) | GPS 속도 |
| 급제동 | STM32의 IMU 브레이크 플래그(`0x13`) | 속도 변화로 직접 추정 (약 0.3g 이상 감속) |
| K값 | STM32 센서 요약(`0x10`) | 없음(N/A) |

STM32가 1초 넘게 조용하면 BSM에 `SENSOR_DEGRADED` 비트를 켜서 후방차에 알립니다.

## 파일

| 파일 | 내용 |
|---|---|
| `front_node.py` | **새 실행 파일.** 전방차에서 `v2v_node.py` 대신 실행 |
| `front_logic.py` | 판단 로직(속도/급제동/경고). 하드웨어와 분리돼 있어 노트북에서 시험 가능 |
| `rear_sim.py` | 후방차 흉내. 후방차 V2V가 붙기 전에 전방차 경고 기능만 시험 |
| `test_front_logic.py` | 판단 로직 시험 (28개 항목) |
| `bsm_protocol.py` | 팀 파일에 **급제동 비트 1줄 + `brake` 속성만 추가** |
| `aiv_uart_rx.py` | 홈 폴더의 것과 같은 파일 (같은 폴더에서 import 하려고 복사) |

## 실행

```bash
cd ~/v2v
python3 test_front_logic.py                                   # 판단 로직 시험 (하드웨어 필요 없음)
python3 front_node.py --gps --stm32-port /dev/serial0 --serial-port /dev/ttyUSB0
```
- STM32 없이: `--no-stm32` (GPS 속도와 속도 변화로 급제동 추정)
- ESP32 없이 같은 Wi-Fi에서: `--transport udp`
- GPS 없이 통신만: `--gps` 빼기 (더미 위치)

출력 예
```
*** 경고 ON: 후방차 15.0m (vid1:behind) ***
--- tx=43 speed=40.0km/h(obd) brake=1(imu) gps=Y stm32=OK warn=0 | 후방차=LIVE(lost 0)
*** 경고 OFF ***
```

## 전방차만으로 시험하는 방법 (후방차 V2V 없이)

다른 라즈베리파이나 노트북에 ESP32를 하나 더 꽂고 `rear_sim.py`를 돌립니다. 전방차 BSM을 받아서 그 **뒤 15m**에 있는 것처럼 후방차 BSM을 보내고, 위험 플래그를 3초마다 켰다 껐다 합니다.

```bash
python3 rear_sim.py --serial-port /dev/ttyUSB0           # 경고가 3초마다 켜졌다 꺼져야 정상
python3 rear_sim.py --serial-port /dev/ttyUSB0 --side    # 옆 차선: 경고가 안 떠야 정상
```
`rear_sim.py` 화면에서 전방차의 `brake=1`이 보이면 급제동 전달도 정상입니다.

## 규격 추가 (팀 합의 필요)

1. **BSM STATUS 비트 4 = BRAKE_ACTIVE (급제동)**: 지금 비어 있는 예약 비트라 기존 수신 코드는 무시합니다(호환).
2. **UART `0x20 V2V_WARN` (Pi → STM32)**: 규격 v0.2는 STM32 → Pi 방향뿐이라 새로 추가합니다.

| 항목 | 내용 |
|---|---|
| 프레임 | 기존과 동일 `STX(02) TYPE LEN PAYLOAD XOR ETX(03)`, 리틀엔디안 |
| TYPE / LEN | `0x20` / 4 |
| PAYLOAD | `level`(u8: 0 없음, 1 주의(예약), 2 위험), `src_vid`(u8), `dist_dm`(u16, 0.1m 단위, `0xFFFF`=모름) |
| 주기 | 10Hz. **경고가 없어도 level 0을 계속 보냅니다** |
| STM32 처리 | **500ms 동안 0x20이 안 오면 level 0으로 간주** (라즈베리파이가 죽어도 부저가 계속 울리지 않게) |

## 확인한 것

- `test_front_logic.py` 28개 항목 통과: 0x20 프레임 형식, 속도/급제동 우선순위, 급제동 추정(5 m/s² 감지, 2.5 m/s² 무시), 경고 수락/무시 9가지 상황, 경고 유지, 여러 차 동시 경고.
- **통합 시험** (`front_node` + `rear_sim`을 UDP로 연결, STM32는 가상 시리얼로 흉내):
  - 후방 위험 ON → 0.3초 뒤 STM32로 `0x20 level=2, 15.0m` 전송, OFF 후 1초 유지하고 해제
  - STM32 브레이크 플래그 → 후방차 화면에 `brake=1` 표시
  - `--side`(옆 차선) → 경고가 한 번도 안 켜짐
- 기존 `v2v_node.py`는 바뀐 `bsm_protocol.py`로도 그대로 동작합니다.
- **실제 ESP32·GPS·STM32로는 아직 시험하지 않았습니다.**

## 알려진 한계

- **GPS로는 차선을 구분하지 못합니다.** 옆 차선이지만 비스듬히 뒤에 있는 차(예: 15m 뒤, 3.5m 옆)의 경고는 받아들입니다. 정확히 나란한 옆 차는 걸러집니다.
- **내가 정지해 있으면** 진행방향을 몰라서 100m 안의 경고를 모두 받아들입니다(놓치는 것보다 낫다는 판단).
- 상대 GPS가 무효인 경고도 같은 이유로 받아들입니다.

## 남은 일

1. **전방 STM32 펌웨어**: 지금 펌웨어는 IMU 바이트를 그대로 중계하는 시험용입니다. 규격 프레임(`0x13` IMU+브레이크 플래그, `0x14` OBD, `0x11` 하트비트)을 보내고, `0x20`을 받아 **부저(PA0)/OLED**로 경고하도록 만들어야 합니다. ← 부저 로직은 여기서 만듭니다.
2. **후방차**: 위험 판단 시 BSM에 `DANGER` 비트를 켜서 보내야 전방차가 실제로 경고를 받습니다. 지금 후방 Pi5 코드에는 V2V가 없습니다.
