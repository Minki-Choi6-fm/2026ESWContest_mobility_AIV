# V2V_DEPLOY_NOTES — 전방 RPi4 에 반영할 파일과 확인 방법

대상: 전방차 RPi4 담당(김연수/최민준)과 후방차 담당. 후방 Pi5 에서 이미 반영·시험한 내용입니다 (`v2v/v2v_stack/`, 백업 `*.bak_20261024_142224`).

## 1. 복사할 파일 (후방 Pi5 → 전방 RPi4)
| 파일 | 이유 | sha256 (앞 16자) |
|---|---|---|
| `freshness.py` | **필수.** 상대(후방)가 재시작해 SEQ 가 0부터 다시 시작해도 STALE 이면 SEQ 비교 없이 수락. 이 수정이 없으면 수신 쪽 차량이 재시작한 송신 차량의 프레임을 SEQ가 옛 값을 넘을 때까지 전부 버림 (측정: 76/76 거절, 복구 없음). **양쪽 차량 모두 수신하므로 양쪽에 필요** | `bf63d3555e8da057` |
| `bsm_protocol.py` | STATUS bit 4–6 ([PROPOSAL]) 상수/인자. 기존 호출은 그대로, 프레임 26 B·CRC 불변. 옛 버전과 **상호 운용 가능**(옛 디코더가 새 프레임을 CRC 통과로 받고 bit 0–3 동일) — 단 옛 쪽은 bit 4–6 을 모름 | `b308b16056b30251` |
| `transport.py`, `v2v_node.py` | 변경 없음(같은 파일 유지). 참고용 | `879cab4c37119d1d`, `07f9c45c71e81bbf` |
| `v2v_compat_test.py` (+ `*.bak_20261024_142224` 2개) | 호환성 시험용. 시험 스크립트는 같은 폴더의 `.bak_*` 를 읽음 | — |

복사 후 확인: `sha256sum freshness.py bsm_protocol.py | cut -c1-16` 가 위 값과 같은지 → `python3 v2v_compat_test.py <v2v 파일이 있는 폴더>` 가 `ALL PASS`(13개) → `python3 bsm_protocol.py` 자체 시험.

## 2. 전송 설정 주의
- UDP 시험 시 `--broadcast-addr 255.255.255.255` 는 같은 핫스팟의 모든 기기에 닿음. 서브넷 브로드캐스트(예: `172.19.31.255`)를 쓰고 팀원 노드와 포트(9000)가 겹치지 않게 조율. 한 PC에서 노드 2개는 9000에서도 동작함(측정) — 시험은 루프백 브로드캐스트 `127.255.255.255` + 포트 19000 사용.
- STATUS bit 4–6 은 아직 팀 합의 전 [PROPOSAL] 입니다. 전방차가 이 비트를 읽어 동작을 바꾸려면 합의가 먼저.

## 3. ESP-NOW 브리지 (.ino) — 확인된 문제
- `v2v_stack/esp32_espnow_bridge/esp32_espnow_bridge.ino` (9/27) 는 **RSSI 를 기록하지 않음** (수신 콜백이 프레임만 시리얼로 통과). 시험 보고서의 RSSI 지표를 쓰려면 RSSI 를 출력하는 버전이 필요.
- **정정(S8):** 10/16 에 RSSI 를 찍은 것은 Pi5 에 이미 있는 `esp_now_ping_test.ino`(홈 `~/esp_now_ping_test/`, 사본 `v2v/esp32/esp_now_ping_test/`; 코어 3.x 시그니처 `info->rx_ctrl->rssi`) 이고, 그 출력 로그가 **`~/range_rear.log`**(10/16 18:40, 119줄)입니다. 측정값: **RSSI −80 … −42 dBm, 중앙값 −56 dBm; 초당 수신 10개(10 Hz); 손실률 0.0 %**(마지막 줄 `total=7490 lost=1`). **거리·안테나 조건은 로그에 없음(미확인).** 이것은 핑 시험이고 **BSM 브리지(.ino)에는 RSSI 출력이 없음** — 차량 시험에서 BSM 과 RSSI 를 함께 기록하려면 브리지에 RSSI 출력을 추가한 코어 3.x 용 버전이 필요.
- **Pi5 에서 컴파일 확인(업로드는 안 함):** 설치된 `esp32:esp32` 코어는 **3.3.12**. 9/27 브리지 `.ino` 는 코어 2.x 용 콜백 시그니처라 **컴파일 오류**(`esp_now_register_send_cb` 인자 타입 불일치 등). 주석에도 코어 3.x 에서는 `onDataRecv`/`onDataSent` 시그니처 수정이 필요하다고 적혀 있음.
- **최민준 님께 확인할 것:** (1) `range_rear.log` 를 만든 조건(두 ESP32 의 거리, 안테나 연결, 어느 보드), (2) BSM 브리지의 **코어 3.x 호환 버전(RSSI 출력 포함)** 이 따로 있는지 — 있으면 `v2v/esp32/` 에 새 폴더로 보관(덮어쓰기 금지). 펌웨어 업로드는 승인 후.

## 4. ESP32 안테나(U.FL) 확인 항목
- [ ] 후방/전방 ESP32 보드 모두 U.FL 커넥터에 **외부 안테나 연결** (보드에 안테나 선택 점퍼/저항이 있는 모델이면 외부 안테나 쪽으로 설정된 것 확인)
- [ ] 안테나가 금속 케이스/배선 다발 바로 옆에 있지 않은지, 차 안에서 창 쪽에 두었는지
- [ ] USB 케이블/허브 상태, `ls -l /dev/serial/by-id/` 에 CP2102 가 보이는지 (현재 `/dev/ttyUSB0` = CP2102, ESP32 보드의 USB-UART 일 가능성 [가설])
- [ ] 전방/후방에서 같은 펌웨어·같은 Wi-Fi 채널 설정(ESP-NOW)인지
- [ ] 정지 상태에서 5 m / 20 m / 50 m 간격 핑(`esp_now_ping_test`)으로 RSSI·손실을 먼저 기록해 두기
