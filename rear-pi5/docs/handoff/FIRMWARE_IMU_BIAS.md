# FIRMWARE_IMU_BIAS — IMU 정차 편향을 펌웨어에서 보정하는 옵션 (참고용, 구현 안 함)

## 현재 상태 (측정)
- `main_v18c.c`: 브레이크 추정은 **보정하지 않은 `ax`** 로 한다 — `ax <= -100 mg` 가 3샘플(≈150 ms) 이어지면 ON, `> -80 mg` 면 OFF (`BRAKE_ON_MG`, `BRAKE_OFF_MG`, `BRAKE_ON_COUNT`).
- Pi5 로그 분석(`k_estimator.py`, 정차 23곳/11곳/2곳): 정차 중 acc_x 중앙값(편향)이 **+60 … +113 mg** 이고 같은 시점 IMU 피치와 **편향 = −1000·sin(피치)** 로 거의 정확히 일치 (상관 −1.00, 차이 ≈ 1–2 mg; 예: 피치 −6.2° ↔ +107 mg). 즉 편향은 **장착 각도/도로 경사에 의한 중력 성분**.
- 영향: 센서가 약 −5°로 기울어 있으므로 raw `ax` 에는 약 **+90 mg 가 더해져** 있음. "ax ≤ −100 mg" 는 실제 감속으로는 **약 −190 mg(0.19 g)** 이라는 뜻 → 보통 제동(0.1–0.15 g)은 BRAKE_ACTIVE 가 거의 안 켜질 것 [가설: 로그의 단발 플래그와 일치]. 로그에서 플래그가 켜진 샘플은 주행당 4/10/20개(0.0–0.2 %)로, 대부분 1샘플짜리 단발이었음.

## 펌웨어 쪽 옵션
| # | 옵션 | 영향 |
|---|---|---|
| A | 정차 감지(0x14 OBD 속도 0 ≥ 2 s 또는 레이더 정지 + IMU 분산 작음) 동안 `ax` 이동평균을 편향으로 저장, 이후 `ax_corr = ax − bias` 로 `brake_active` 판단 | BRAKE_ACTIVE 가 실제 감속(≥0.1 g)에 맞아짐 → BSM `BRAKE_ACTIVE`(bit4 [PROPOSAL]) 의미가 정확해짐. 0x13 로 보내는 `acc_mg` 를 보정값으로 바꿀지(규격 변경)·원값 유지하고 별도 필드를 추가할지 결정 필요 |
| B | 피치 사용: `ax_corr = ax + 1000·sin(pitch)` (정차 편향이 위 식과 일치함) | 정차를 기다리지 않아도 보정, 경사 변화에 따라감. **단 모듈이 내는 피치가 가속도계 기반이라면 제동 중 피치가 같이 변해 감속의 일부가 지워질 수 있음** — Pi5 `dpitch` 분석(이벤트 2–3개뿐)으로는 확인 불가. 실차에서 제동 시 피치 변화 확인 후 결정 |
| C | 지금처럼 두고 Pi5 에서만 보정(현 구현) | 펌웨어 변경 없음. BRAKE_ACTIVE 는 계속 부정확하므로 BSM bit4 를 쓰려면 Pi5 쪽 판정으로 대체해야 함 |

## 영향 정리
- 규칙 10(BSM brake status = IMU 감속 추정 ≤ −0.1 g)의 임계값은 **보정 후 값 기준**이어야 의미가 맞음.
- 펌웨어 수정은 승인 필요(플래시 포함). 타임아웃 100 ms·IWDG 40 ms·K 범위(0.3–1.0)와 무관하지만 `proto_task()` 에 상태(정차 판정)가 추가됨.
- Pi5 쪽 K 추정은 어느 옵션이든 동작함(자체 보정 사용). 펌웨어가 보정하면 Pi5 보정은 중복이므로 한쪽만 쓰도록 정할 것.
